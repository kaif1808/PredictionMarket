# ABM Technical Guide

This document specifies the exact runtime behavior of the ABM implementation in `calibration/abm/`.
It is implementation-oriented and anchored to current code paths:
- `calibration/abm/config.py`
- `calibration/abm/profiles.py`
- `calibration/abm/agents.py`
- `calibration/abm/runner.py`
- `calibration/abm/calibrate.py`

## 1. System Architecture

The ABM does not implement its own market engine. It reuses production server components:
- Price and cost math: `server.lmsr`
- Belief update helper: `server.bayesian`
- Trade validation and state transitions: `server.orchestrator.Orchestrator`

A session is simulated by:
1. Creating participants `P01..PN`.
2. Assigning each a behavioral profile and a per-agent risk-aversion draw.
3. Running optional practice market (market `0`, round `1`).
4. Running real markets `1..4`, each with rounds `1..5`.
5. For each round: generating a continuous-time event stream and processing events in timestamp order.

## 2. Determinism Model

Determinism is achieved via SHA256-derived seeds and local `random.Random` instances.

### 2.1 Seed construction
- Agent-level seeds (`agents.py`):
  - material: `"{session_id}:{market_id}:{round_id}:{participant_id}:{profile_name}:{step}"`
- Runner-level arrival seeds (`runner.py`):
  - material: `"{session_id}:{market_id}:{round_id}:{participant_id}:{step}"`

### 2.2 Seeded steps
- `step="arrivals"`: legacy homogeneous event-time stream.
- `step="arrivals_gap"`: NHPP thinning candidate gaps per participant.
- `step="arrivals_accept"`: NHPP thinning acceptance draws per participant.
- `step=f"belief:{event_index}"`: belief update randomness (signal flipping noise).
- `step=f"decide:{event_index}"`: action-side draw, activation draw, size randomness.

Given identical config and code, reruns are deterministic.

## 3. Event-Time Round Execution

In `_run_market_round()` (`runner.py`):

1. Round is opened via orchestrator.
2. Per-round volatility state is initialized:
   - `ema_abs_return = 0.0`
3. For each agent, candidate times are generated by exponential gaps at proposal rate:
   - State-hybrid mode: `proposal_rate = lambda_max`
   - Legacy mode: `proposal_rate = event_intensity`
   - candidate times are merged globally with a min-heap and processed in timestamp order.
4. In state-hybrid mode, each candidate is accepted via Ogata thinning:
   - `edge_i = clip(|belief_i - price| / 0.5, 0, 1)`
   - `vol_t = clip(ema_abs_return / vol_ref, 0, 1)`
   - `lambda_i(t) = clip(lambda_base * (1 + edge_gain * edge_i^edge_exp) * (1 + vol_gain * vol_t^vol_exp), lambda_min, lambda_max)`
   - accept if `U <= lambda_i(t) / lambda_max`
5. At each accepted event:
   - Reload live DB snapshot (`Market`, `Round`, `MarketRole`, `Signal` for that participant).
   - Compute current LMSR price from live `q_yes`, `q_no`, `b`.
   - Update belief.
   - Decide zero or more trades.
   - Submit each trade through `orch.record_trade(...)`.
   - After each accepted trade: update volatility state
     - `ema_abs_return <- vol_ema_alpha * |price_after - price_before| + (1 - vol_ema_alpha) * ema_abs_return`
6. Trade timestamps are rewritten to virtual time:
   - `executed_at = round_base + timedelta(seconds=event_time_s, microseconds=trade_seq)`.
7. Round is closed via orchestrator.

Key implications:
- No stale in-memory market state is used for decisions.
- Execution is CPU-fast; simulated time is virtual.
- Trade timestamps are monotonic within a round.

### 3.1 Is the number of decision opportunities fixed?

No. It is random, not fixed.

In default `state_hybrid` mode, opportunities are NHPP and state-dependent:
- Candidate points are proposed by a homogeneous process at `lambda_max`.
- Candidates are thinned by state intensity `lambda_i(t)` (edge + volatility terms).
- Accepted opportunity counts are random and adapt to market state.

In optional `legacy_homogeneous` mode, opportunities revert to:
- `N_i ~ Poisson(event_intensity * round_duration_s)`.

There are two reasons this still can look like “few trades”:
- Opportunity does not imply order submission: each event passes edge, affordability/holding, side-selection, and activation gates.
- Opportunity does not imply large notional: quantity is separately sampled and clipped by budget/inventory.

### 3.2 Event scheduler pseudocode

```text
ema_abs_return <- 0.0
proposal_rate <- (lambda_max if intensity_mode=state_hybrid else event_intensity)

for participant in sorted(participants):
    gap_rng <- seeded_rng(..., "arrivals_gap" or "arrivals")
    accept_rng <- seeded_rng(..., "arrivals_accept")
    t1 <- Exp(rate=proposal_rate)
    if t1 <= round_duration_s:
        push (t1, participant, candidate_idx=0) to min-heap

while heap not empty:
    (t, participant, candidate_idx) <- pop earliest event
    snapshot <- read live market/role/signal state from DB

    if intensity_mode=state_hybrid:
        edge_i <- clip(|belief - price|/0.5, 0, 1)
        vol_t <- clip(ema_abs_return/vol_ref, 0, 1)
        lambda_i <- clip(lambda_base*(1+edge_gain*edge_i^edge_exp)*(1+vol_gain*vol_t^vol_exp), lambda_min, lambda_max)
        accept <- U(0,1) <= lambda_i / lambda_max
    else:
        accept <- True

    if accept:
        belief <- update_belief(snapshot, event_index=accepted_idx)
        orders <- decide(snapshot, belief, event_index=accepted_idx)
        accepted_idx <- accepted_idx + 1
    else:
        orders <- []

    for order in orders:
        trade <- record_trade(order) through orchestrator
        ema_abs_return <- alpha*|trade.price_after-trade.price_before| + (1-alpha)*ema_abs_return
        overwrite executed_at with virtual timestamp

    next_t <- t + Exp(rate=proposal_rate)
    if next_t <= round_duration_s:
        push (next_t, participant, candidate_idx+1) to heap
```

## 4. Profile Layer and Risk Heterogeneity

## 4.1 Profile assignment
`assign_profiles(participant_ids, mix)`:
- Parse `profile_mix` (e.g. `"rational:5,herder:2,noise:2"`).
- Sort participant ids lexicographically.
- Assign in order; if participants exceed list length, cycle profiles.

Default preset values (`profiles.py`):
- `rational`: `risk_aversion=0.30`, `bias=0.01`, `stubbornness=0.15`, `expertise=0.95`, `market_imitation=0.15`, `budget_variance=0.05`
- `noise`: `risk_aversion=0.65`, `bias=-0.12`, `stubbornness=0.20`, `expertise=0.55`, `market_imitation=0.45`, `budget_variance=0.70`
- `herder`: `risk_aversion=0.45`, `bias=0.08`, `stubbornness=0.30`, `expertise=0.75`, `market_imitation=0.70`, `budget_variance=0.20`
- Additional presets exist: `stubborn`, `overreact`.

## 4.2 Per-agent risk-aversion draw
`assign_risk_aversion(...)`:
- Draw from Gaussian `N(mean=ra_mean, sd=ra_sd)`.
- Accept only draws in `[ra_lo, ra_hi]` (rejection sampling, up to 1024 attempts).
- Fallback clamp if no accepted draw in 1024 tries.
- Draw order is deterministic by sorted participant ids.

Then `apply_risk_aversion(...)` overwrites each assigned profile's `risk_aversion` field.

## 4.3 Deprecated hard override
If `SimConfig.risk_aversion` is non-`None`, `_apply_risk_override(...)` forcibly sets all agents to that scalar, overriding heterogeneity.

## 5. Belief Update Equation

`Agent.init_market()` starts market belief at:
- `belief_0 = clamp(0.5 + bias, 0.01, 0.99)`

For each event (`update_belief(...)`):

1. Start from current belief `b_t`.
2. If a signal is delivered:
   - Effective signal quality:
     - `theta_eff = clamp(0.5 + (signal_theta - 0.5) * expertise, 0.51, 0.99)`
   - With probability `(1 - expertise)`, flip signal `H <-> L`.
   - Compute Bayesian posterior `raw_post` via `bayesian.update_posterior(...)`.
   - Stubbornness blend:
     - `post = b_t + (1 - stubbornness) * (raw_post - b_t)`
3. Market-imitation blend:
   - `belief_{t+1} = clamp(post + market_imitation * (current_price - post), 0.01, 0.99)`

## 6. Decision Policy (Buy/Sell/Hold)

`Agent.decide(...)` inputs:
- State: `q_yes`, `q_no`, `b`, `balance`, `yes_held`, `no_held`
- Controls: `edge_threshold`, `sell_propensity`, `order_size_dist`
- Randomness seed: `decide:{event_index}`

### 6.1 Edge and no-trade band
- Market price: `p = lmsr.price(q_yes, q_no, b)`
- Edge: `edge = belief - p`, `abs_edge = |edge|`
- If `abs_edge < edge_threshold`: hold (no order)

### 6.2 Candidate directions
- If `edge > 0`: buy `yes`, sell `no`
- If `edge < 0`: buy `no`, sell `yes`

### 6.3 Capacity constraints
- Buy capacity:
  - `affordable = lmsr.max_purchasable(...)`
  - `affordable_qty = floor(affordable)`
- Sell capacity:
  - `held_qty = floor(held contracts on sell side)`

### 6.4 Action scoring
- `risk_scale = max(0, 1 - risk_aversion)`
- `edge_scale = min(1, abs_edge / 0.5)`
- `buy_score  = risk_scale * edge_scale` if `affordable_qty > 0` else `0`
- `sell_score = sell_propensity * risk_scale * edge_scale` if `held_qty > 0` else `0`

If both scores are zero: hold.

### 6.5 Side selection
- If `sell_propensity >= 1.0` and `sell_score > 0`: force sell path.
- Else if both buy and sell scores positive:
  - `P(sell) = sell_score / (buy_score + sell_score)`
- Else choose whichever side has positive score.

### 6.6 Activation gate
Even after choosing side, action can be skipped:
- `activation = min(1.0, 0.55 + 0.45 * max(buy_score, sell_score))`
- Execute action only if `rng.random() <= activation`

### 6.7 Order size sampling
First draw `base_draw` from `order_size_dist` (capped at `min(20, action_budget)`).

Supported specs:
- `geometric:p=<p>,tail=<tail>`
  - with probability `tail`, draw uniform integer in `[min(5,max_qty), max_qty]`
  - else draw geometric-like value:
    - `draw = ceil(log(1-u)/log(1-p))`, clipped to `[1,max_qty]`
- `powerlaw:alpha=<alpha>` (alias `zipf`)
  - sample from discrete weights `w_k = 1/k^alpha`, `k=1..max_qty`
- unknown format fallback: uniform integer `[1,max_qty]`

Then apply score/jitter scaling:
- `jitter = 1 + budget_variance * (2u - 1)`
- `qty = round(base_draw * (0.60 + 1.80 * max_score) * jitter)`
- `qty` clipped to `[1, action_budget]`

Finally chunk into `TradeRequest`s of max 20 each.

### 6.8 Engine-side hard constraints
`orch.record_trade(...)` enforces:
- No short-selling (`sell quantity <= holdings`)
- Sufficient funds for buys
- Position and balances updated atomically

### 6.9 Full decision algorithm pseudocode

```text
input: belief, q_yes, q_no, b, balance, yes_held, no_held, params
p <- LMSR_price(q_yes, q_no, b)
edge <- belief - p
if |edge| < edge_threshold:
    return []

buy_direction  <- "yes" if edge > 0 else "no"
sell_direction <- opposite side
affordable_qty <- floor(max_purchasable(balance, buy_direction))
held_qty <- floor(contracts held on sell_direction)

risk_scale <- max(0, 1 - risk_aversion)
edge_scale <- min(1, |edge| / 0.5)
buy_score  <- risk_scale * edge_scale if affordable_qty > 0 else 0
sell_score <- sell_propensity * risk_scale * edge_scale if held_qty > 0 else 0
if buy_score == 0 and sell_score == 0:
    return []

if sell_propensity >= 1 and sell_score > 0:
    side <- sell
elif buy_score > 0 and sell_score > 0:
    side <- sell with prob sell_score/(buy_score + sell_score), else buy
elif sell_score > 0:
    side <- sell
else:
    side <- buy

action_budget <- affordable_qty if side=buy else held_qty
if action_budget <= 0:
    return []

activation <- min(1, 0.55 + 0.45 * max(buy_score, sell_score))
if U(0,1) > activation:
    return []

base_draw <- sample_order_size(order_size_dist, max_qty=min(20, action_budget))
jitter <- 1 + budget_variance * (2U(0,1)-1)
qty <- round(base_draw * (0.60 + 1.80*max(buy_score, sell_score)) * jitter)
qty <- clip(qty, 1, action_budget)

return qty split into chunks of <= 20
```

## 8. Effective Defaults vs Function Fallbacks

Important nuance:
- Runtime ABM sessions call `Agent.decide(...)` through `runner.py` and explicitly pass `edge_threshold`, `sell_propensity`, `order_size_dist` from `SimConfig`.
- `Agent.decide(...)` still has internal signature defaults (`edge_threshold=0.02`, `sell_propensity=0.42`), which only apply if someone calls `Agent.decide()` directly outside runner wiring.

## 9. Calibration Harness (Decision-Relevant)

`calibration/abm/calibrate.py` sweeps decision-relevant knobs and scores against `experiment_1`:
- Swept fields: `lambda_base`, `edge_gain`, `edge_exp`, `vol_gain`, `vol_exp`, `vol_ema_alpha`, `vol_ref`, `lambda_min`, `lambda_max`, `sell_propensity`, `edge_threshold`, `ra_mean`, `ra_sd`, `order_size_dist`, `seed`
- Primary fit metrics:
  - `trades_per_agent_round`
  - `quantity_per_agent_round`
  - `median_order_size`
  - `sell_share`
  - `negative_cost_share`
- Gate:
  - each primary ratio in `[0.5, 1.5]`
  - all 4 non-practice markets active

`extract_reference_targets()` also cross-checks `experiment_1` vs `export_1` trade IDs and row counts, failing loudly on mismatch.

## 10. Tuning Playbook (Mechanistic Effects)

- Increase `lambda_base`: raises baseline accepted opportunity rate.
- Increase `edge_gain`: makes opportunities more sensitive to belief-price mispricing.
- Increase `vol_gain`: raises opportunities during volatile periods.
- Decrease `vol_ref`: makes volatility response activate earlier.
- Increase `lambda_max`: higher NHPP proposal envelope and potential acceptance ceiling.
- Increase `sell_propensity`: higher sell share and negative-cost-trade share.
- Decrease `edge_threshold`: more frequent trading near fair value.
- Increase `tail` in geometric size spec: more large orders.
- Decrease `ra_mean`: more aggressive (higher `risk_scale`) trading and larger quantities.
- Increase `budget_variance` in profiles: wider stochastic spread in size.
- Change profile mix: shifts signal processing behavior and trend-following via `expertise`, `stubbornness`, `market_imitation`.
